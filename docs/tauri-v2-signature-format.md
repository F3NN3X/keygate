# Tauri v2 updater: signature & public-key format

This documents a correctness fix to keygate's **Tauri** release feed and public-key export. It is written
for anyone maintaining keygate (this fork or upstream `tabloy/keygate`): the previous format did **not**
verify in the current Tauri updater and every self-update failed in the field. If you ship releases to
Tauri v2 clients, you want this change.

## TL;DR

- keygate emitted a **raw, un-base64-wrapped, 2-line** minisign signature and a **bare** public key.
- Tauri v2's updater (`tauri-plugin-updater` ≥ 2, backed by `minisign-verify`) requires a **base64-encoded
  full minisign file** for *both* the config `pubkey` and the feed `signature`, and the signature must be
  the **4-line** minisign form including a **global signature**.
- The mismatch made the client fail at the very first step — base64-decoding the public key — surfacing as:
  `The signature <pubkey> could not be decoded, please check if it is a valid base64 string. The signature
  must be the contents of the .sig file generated by the Tauri bundler, as a string.`
- Fix: `TauriPublicKey` and `TauriSignatureEnvelope` now emit the base64-wrapped full minisign files, and
  the signing service computes and stores a **global signature** (new `ed25519_global_sig` column).

## What Tauri v2 actually does

`tauri-plugin-updater`'s `verify_signature` (v2.11 shown; behaviour is stable across v2):

```rust
fn verify_signature(data: &[u8], release_signature: &str, pub_key: &str) -> Result<()> {
    let pub_key_decoded = base64_to_string(pub_key)?;          // (1) base64-DECODE the config pubkey → text
    let public_key = PublicKey::decode(&pub_key_decoded)?;     // (2) parse a minisign .pub (2 lines)
    let signature_base64_decoded = base64_to_string(release_signature)?; // (3) base64-DECODE the feed signature → text
    let signature = Signature::decode(&signature_base64_decoded)?;       // (4) parse a minisign .sig (4 lines)
    public_key.verify(data, &signature, true)?;               // (5) verify FILE sig AND GLOBAL sig (allow_legacy=true)
    Ok(())
}

fn base64_to_string(s: &str) -> Result<String> {
    let decoded = base64::STANDARD.decode(s)?;                 // must be valid base64…
    Ok(std::str::from_utf8(&decoded)?.to_string())             // …that decodes to valid UTF-8 text
}
```

`minisign-verify` (0.2.5) then enforces:

- **`PublicKey::decode`** expects **2 lines**: an `untrusted comment:` line, then a base64 line that decodes
  to a **42-byte** blob `"Ed"(2) + key_id(8) + key(32)`.
- **`Signature::decode`** expects **4 lines**: an `untrusted comment:` line; a base64 line decoding to a
  **74-byte** blob `"Ed"(2) + key_id(8) + sig(64)`; a `trusted comment: ` line; and a base64 line decoding
  to a **64-byte global signature**.
- **`verify_ed25519`** checks **both**: `ed25519.Verify(key, file_bytes, sig)` **and**
  `ed25519.Verify(key, sig ‖ trusted_comment_body, global_signature)`, where `trusted_comment_body` is the
  text of the `trusted comment: ` line **after** its 17-char prefix. `allow_legacy: true` is passed, so the
  legacy `Ed` algorithm (sign over the raw file, not a BLAKE2b prehash) is accepted — no need to prehash.

The essential, easy-to-miss points: (a) the `pubkey` and `signature` strings are each **base64 of an entire
minisign file's text**, not the inner key/sig blob; and (b) the signature is the **full** minisign form with
a **global signature**, which only the private key can produce.

## What keygate emitted before (both wrong)

```
# pubkey (tauri-pubkey endpoint / TauriPublicKey):
RWR2...QczU2                          # = base64("Ed"+key_id+key); NOT base64 of a .pub file

# feed signature (TauriSignatureEnvelope):
untrusted comment: signature from keygate\nRWR2...   # raw 2-line text; NOT base64-wrapped; no global sig
```

Step (1) `base64_to_string(pubkey)` base64-decodes `RWR2...` to the 42-byte blob, whose bytes are **not valid
UTF-8**, so it errors immediately — and because the shared helper's error text is worded for signatures, the
message names the *pubkey* value. The feed signature was equally wrong: the raw text isn't valid base64, and
even wrapped it is only 2 lines (no `trusted comment:` / global signature) so `Signature::decode` would reject
it. (The comment in `BuildTauri` describing `signature[0..2] == "Ed"` reflected an older Tauri v1-era verifier
and was the source of the wrong mental model.)

## What keygate emits now (correct)

```
# pubkey → base64 of this 2-line .pub file:
untrusted comment: minisign public key
RWR2...QczU2                          # base64("Ed"+key_id+key)

# feed signature → base64 of this 4-line .sig file:
untrusted comment: signature from keygate
<base64("Ed"+key_id+file_sig_64)>     # 74 bytes
trusted comment: keygate release
<base64(global_sig_64)>               # ed25519(priv, file_sig_64 ‖ "keygate release")
```

The trusted-comment body is a fixed string (`keygate release`) so sign-time and feed-time agree without an
extra stored column; `minisign-verify` treats the body as opaque.

## Changes

| File | Change |
|---|---|
| `db/migrations/20260906_release_artifact_global_sig.{up,down}.sql` | Add `ed25519_global_sig TEXT NOT NULL DEFAULT ''` to `release_artifacts`. |
| `internal/model/model.go` | `ReleaseArtifact.Ed25519GlobalSig` field. |
| `internal/service/release_signing.go` | `SignResult.GlobalSignature`; `SignArtifactWith` computes `ed25519(priv, file_sig ‖ tauriTrustedComment)` at sign time (the only place the private key is in hand). |
| `internal/service/release_feed.go` | `TauriPublicKey` → base64 of the 2-line `.pub`; `TauriSignatureEnvelope(fileSig, globalSig, pub)` → base64 of the 4-line `.sig`; `tauriTrustedComment` constant; `BuildTauri` passes the artifact's global sig; corrected doc comments. |
| `internal/store/release.go` | `UpdateArtifactSignature` persists the global sig; the **publish gate** (`PublishRelease` + `diagnoseUnpublishable`) requires `ed25519_global_sig != ''` when `requireSignatures` — a missing global sig makes `TauriSignatureEnvelope` return `""`, so a "signed" release would otherwise ship an unverifiable feed; both signature-clearing paths (`UpdateArtifactFile`, `ClearReleaseSignatures`) also clear it. |
| `internal/service/release_feed_test.go` | Replaced `TestTauriSignatureEnvelopeMatchesVerifier` (which asserted the wrong 2-line shape) with `TestTauriEnvelopeVerifiesLikeTauri`, which reproduces Tauri's exact verify path — base64-decode → parse 4 lines → verify file sig **and** global sig — and asserts the output passes. |

Sparkle (`RenderSparkle`) and Velopack (`BuildVelopack`) are untouched: they read the raw `Ed25519Sig`
directly and never use the Tauri envelope or the global signature.

## Backward compatibility

- The migration is additive; the column defaults to `''`.
- Releases signed **before** this change have no global signature. Their Tauri feed signature is now emitted
  as `""` (unsigned) rather than a broken value, and — because of the publish-gate invariant above — such a
  release cannot be (re-)published as signed until it is **re-signed by re-publishing**. Re-publish any release
  a Tauri client must accept.
- Clients embed the `pubkey` at build time. After deploying this, the **new** base64-wrapped value from
  `GET /admin/products/:id/signing-key/tauri-pubkey` must be pinned in the app's `tauri.conf.json` and the app
  rebuilt; a client that pins the old bare-blob value can never verify (it fails at step 1), independent of
  which format the feed uses.

## Verification

- `go vet ./...` and `go test ./... -count=1` pass in `golang:1.25-alpine`.
- `TestTauriEnvelopeVerifiesLikeTauri` is the load-bearing test: it generates a real keypair, signs a message,
  computes the global signature, builds the envelope + pubkey, then performs Tauri's verification steps in Go
  and asserts both signatures validate. It fails against the old 2-line/bare formats.

## Upstreaming note

This is not DeckShot-specific — it is a correctness fix for any Tauri v2 consumer of keygate's release feed.
It is a candidate for `tabloy/keygate`'s `main`. The only opinionated choice is the fixed trusted-comment body
(`keygate release`); upstream may prefer a timestamped comment (store it per-artifact if so, since the global
signature must be computed over whatever text the feed later emits).
